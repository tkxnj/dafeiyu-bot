# 调教指南：让大肥鱼变成你们群的形状

同一个模型，人设和参数不同，效果能差出十万八千里。这篇是实操手册，建议按顺序做一遍。

---

## 1. 先想清楚：你要它当什么角色

先回答三个问题，再动手写人设：

1. 你们群是什么氛围？（熟人小群 / 兴趣群 / 大学班级群 / 工作群）
2. 你希望它像谁？（毒舌群友 / 温柔捧哏 / 懂哥 / 复读机 / 潜水员）
3. 你最怕它干什么？（刷屏 / 说教 / 抢话 / 乱开黄腔 / 装熟）

答案会决定三件事：人设怎么写、`REPLY_RATE` 多高、禁区列什么。

---

## 2. 人设文件怎么写（`prompts/persona.md`）

推荐结构（当前文件就是按这个组织的）：

```markdown
# 角色卡：XXX
一段话说清「你是谁、在哪个群、什么身份」

## 性格
- 3~6 条，有优点也有小毛病（完美角色没有灵魂）
- 写具体行为，别只写形容词：「被夸会得意」比「幽默」有用

## 说话方式
- 句子长度、口头禅、自称、能不能用网络用语
- 明确「不要」什么：不要小作文、不要客服腔、不要每句反问

## 群聊原则
- 被 @ 必回；别人认真聊正事时少插嘴
- 不刷屏、不站队、不当裁判

## 禁区
- 违规内容、人身攻击、隐私、广告
- 遇到有人求助/情绪低落怎么处理

## 风格示例
- 群友：…… → 大肥鱼：……
- 4~6 组即可，宁缺毋滥
```

### 写人设的三个坑

1. **写太满**：把每条规矩都写死，模型会变得僵硬、像在念稿。留 30% 让它自己发挥。
2. **只说形容词**：「幽默风趣、学识渊博」这种模型根本抓不住。换成具体场景：「别人发加班，你会嘴一句老板」。
3. **示例太多太长**：超过 6 组示例会挤占上下文，还容易让它复读示例句式。挑最有代表性的。

### 想要更有「群味」

- 把你们群的黑话、外号、梗写进人设（注意别写别人的隐私）。
- 让它知道群里有谁：不必列名单，但可以写「群里有个总在深夜发吃的的人」。
- 语气示例直接从真实聊天记录里挑（打码后），效果比编的强。

## 3. 去「AI 味」的实操清单

模型一开口就露馅，通常是因为这些句式。人设里明确禁掉：

- ❌「作为一个人工智能…」「希望对你有帮助」「请问还有什么可以帮您」
- ❌「首先…其次…最后…」「综上所述」「值得注意的是」
- ❌ 每句都反问、每句都加 emoji、每句都「哈哈」
- ❌ 动辄 200 字小作文，列 1/2/3 点
- ❌ 过度共情：「我理解你的感受，这确实不容易」——群聊里没几个人这么说话

可以加的正向约束：

- 「一次只说 1~3 句，超过 60 字就拆开发」
- 「不知道就说不知道，别编」
- 「可以反驳别人，但别说教」
- 「偶尔用括号补充心里话」

代码侧也能帮忙：

- `MAX_REPLY_CHARS` 截短
- `MULTI_BUBBLE=true` 拆气泡
- `sanitizeReply()` 去前缀、去 Markdown（已实现）
- `temperature` 1.0~1.3，太低会像客服，太高会发癫

## 4. 参数怎么调（`.env`）

### 4.1 一张表看懂

| 参数 | 影响 | 太小 | 太大 |
| --- | --- | --- | --- |
| `REPLY_RATE` | 没被叫到时插话概率 | 像死人 | 像刷屏机 |
| `COOLDOWN_SECONDS` | 主动接话最小间隔 | 连着说 | 半天不理人 |
| `MAX_REPLIES_PER_HOUR` | 每小时硬上限 | 说两句就哑 | 烧钱+招烦 |
| `CONTEXT_TURNS` | 上下文条数 | 听不懂前文 | 费 token、跑题 |
| `MAX_REPLY_CHARS` | 回复长度上限 | 像电报 | 小作文 |
| `LLM_TEMPERATURE` | 发挥程度 | 复读机 | 胡言乱语 |
| `QUIET_HOURS` | 静音时段 | 半夜扰民 | 白天也哑 |

### 4.2 三个配方

**A. 怕烦人 / 怕风控（推荐先跑这个）**

```env
REPLY_RATE=0.01
COOLDOWN_SECONDS=120
MAX_REPLIES_PER_HOUR=8
CONTEXT_TURNS=10
QUIET_HOURS=0-8
```

**B. 正常群友（跑顺了换这个）**

```env
REPLY_RATE=0.06
COOLDOWN_SECONDS=20
MAX_REPLIES_PER_HOUR=40
CONTEXT_TURNS=16
```

**C. 熟人小群社牛（别在大群用）**

```env
REPLY_RATE=0.25
COOLDOWN_SECONDS=8
MAX_REPLIES_PER_HOUR=100
CONTEXT_TURNS=24
```

调参节奏：**一次只改一个参数，观察一两天**。同时改五个，你根本不知道是哪个起了作用。

### 4.3 特殊玩法

- **只当关键词触发器**：`REPLY_RATE=0`，只有 @ 和关键词才回，最省最安全。
- **纯潜水员**：`REPLY_RATE=0` + `TRIGGER_KEYWORDS=` 留空（或写 `none`）→ 只回 @。
- **夜间闭嘴**：`QUIET_HOURS=1-8` 或跨零点 `23-7`。
- **只在几个群工作**：`ALLOWED_GROUPS=群号1,群号2`。

## 5. 分群策略：不同群不同性格

如果 bot 在多个群，可以按群号切换人设/参数。改法很简单：把 `src/index.js` 里读 `persona` 的地方换成按 `groupId` 查表，例如：

```js
const personas = {
  '111111': loadPersona('prompts/persona-study.md'),   // 学习群：正经一点
  '222222': loadPersona('prompts/persona-chat.md'),    // 闲聊群：放飞一点
};
const persona = personas[groupId] ?? defaultPersona;
```

同理，每个群的 `REPLY_RATE` 也可以做成映射。代码里的 `generateReply({ config, persona, history, groupId })` 已经预留了 `groupId`。

## 6. 记忆与隐私

- 默认只记**每个群最近 16 条**，重启保留在 `data/memory.json`。
- 想让 bot「忘掉」：删掉 `data/memory.json` 再启动。
- 完全不想留痕：`.env` 设 `PERSIST_MEMORY=false`。
- 不建议把聊天记录上传到第三方分析服务；真要统计，自己本地处理、先打码。
- 群友如果介意被 bot 记录，合理做法是停用它或告知大家。

---

## 7. 省钱

- 首选：`REPLY_RATE` 调低 + 关键词触发。
- `CONTEXT_TURNS` 从 16 降到 8，输入 token 立刻减一截。
- 人设文件别越长越好，800~1200 字足够；太长每条消息都在为它付费。
- 只让 bot 进需要的群（`ALLOWED_GROUPS`）。
- 想零成本：Ollama 本地跑小模型（`qwen2.5:7b` 之类），代价是吃内存、回复质量下降。

## 8. 上线前的迭代流程

1. **`npm run demo`**：终端里聊 30~50 轮，调人设到「像人」。
2. **拉进测试群**：先按配方 A 或 B 跑一天。
3. **看日志**：触发原因、耗时、失败率。
4. **问群友**：让他们给一句话评价——「太吵 / 太冷 / 太假 / 有点意思」。
5. **一次改一个参数**，再跑一天。
6. 稳定后考虑放到真群，但仍保持克制。

## 9. 常见翻车与处理

| 翻车现场 | 原因 | 处理 |
| --- | --- | --- |
| 复读同一句话 | temperature 太低 / 上下文里自己刚说过 | 调高温度；检查 `CONTEXT_TURNS` |
| 突然说教/共情 | 人设没写死「不当客服」；模型默认倾向 | 加强禁区；`sanitizeReply` 加规则 |
| 开始编事实 | 模型幻觉 | 人设加「不确定就说不知道、不编数据」；必要时加事实核查 |
| 被群友激怒式对线 | 缺少「不站队、不拱火」约束 | 人设补一条；遇敏感话题直接不接 |
| 疯狂刷屏 | `REPLY_RATE`/冷却设置问题，或群里消息太密 | 调低概率、加大冷却、设每小时上限 |
| 回复带「大肥鱼：」 | 模型自作主张 | 已由 `sanitizeReply` 处理；也可以在人设里强调 |
| 群里没人理它还在说 | 随机触发太高 | 调低 `REPLY_RATE`；开 `QUIET_HOURS` |
| 发敏感内容 | 人设禁区不足 / 模型跑偏 | 加关键词过滤层（自己维护敏感词表）；严重就停用 |

## 10. 下一步扩展（按性价比排序）

1. **表情包**：让模型输出 `[emo]` 标记 → 代码随机配一张图。
2. **图片理解**：换视觉模型，把图片段转 URL/base64 传入。
3. **指令**：「大肥鱼闭嘴/上班/换人设」，管理员生效。
4. **长期记忆**：定时总结群聊摘要，塞进 system prompt。
5. **工具调用**：查天气、搜东西、算数。
6. **多群多人设**：见第 5 节。

先跑稳基础版，再往上加。一次加太多，出问题很难定位。
