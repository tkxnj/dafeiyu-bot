# 常见问题 / 排错手册

> 说明：本文按「自行安装 NapCat + OneBot 11」的通用流程编写；NapCat 与登录账号需要你自己准备。日常排错从 D 节开始。

按「装不上 → 连不上 → 不回话 → 说错话 → 账号安全 → 部署维护」的顺序找。

---

## A. 环境与安装

### A1. `node` 不是内部或外部命令

没装 Node.js 或者没进 PATH。去 <https://nodejs.org/zh-cn> 装 LTS，**装完重新打开命令行窗口**再试。

### A2. `npm install` 卡住 / 报网络错误

国内网络先换镜像：

```bat
npm config set registry https://registry.npmmirror.com
npm install
```

公司/校园网有代理的话，设置 `npm config set proxy http://...` 和 `https-proxy`。

### A3. `npm run xxx` 报 `ERR_MODULE_NOT_FOUND`

一般是 `node_modules` 没装好，删掉重装：

```bat
rmdir /s /q node_modules
npm install
```

（先确认 `node -v` ≥ 20。）

### A4. 双击 `启动.bat` 一闪而过

用命令行打开它：在文件夹地址栏输入 `cmd` 回车，然后运行 `启动.bat`，就能看到报错。Windows 的 bat 里中文乱码是编码问题，`启动.bat` 已加 `chcp 65001`；如果还乱，用 Windows Terminal 运行。

## B. 连接 NapCat

### B1. `npm run doctor` 报 NapCat WebSocket 连不上

依次检查：

1. NapCat 进程还在跑吗？小号还在线吗？
2. WebUI → 网络配置里，你建的是 **WebSocket 服务器**（正向），不是 WebSocket 客户端（反向）？
3. 那个配置**启用**了吗？保存/应用了吗？
4. 端口是不是 `3001`？`.env` 的 `ONEBOT_WS_URL` 写的是 `ws://127.0.0.1:3001` 吗？
5. Token 两边一致吗？（NapCat 设了 Token，`.env` 没填 → 连不上；NapCat 没设，`.env` 却填了 → 也可能失败）
6. 防火墙/安全软件拦了吗？（本机 127.0.0.1 一般没事）
7. NapCat 日志里有没有「WebSocket 服务启动」之类的记录？

### B2. 连上又反复断开

- 看 NapCat 是否在重启 / QQ 掉线；
- 同一个 QQ 是否被开了两个客户端（比如你手机上同时登了同一个号，把其中一个踢了）；
- Token 错误有时表现为连上就断；
- 端口冲突：换一个端口，`.env` 同步改。

### B3. NapCat WebUI 打不开

- 用 `http://127.0.0.1:6099/webui`，不要用 `localhost`（有些系统解析到 IPv6 的 `::1`）；
- 确认 NapCat 控制台打印的实际端口（不同版本可能不同）；
- 检查 6099 是否被别的程序占用；
- 看 NapCat 官方文档：<https://napcat.napneko.icu>。

### B4. 我用的不是 NapCat，是 LLOneBot / 其他

本项目只依赖 **OneBot 11**。只要对方开了正向 WebSocket 服务器，把 `ONEBOT_WS_URL`、`ONEBOT_ACCESS_TOKEN` 指向它就行，代码不用改。注意方向别搞反（有些实现默认是反向 WS）。

### B5. WebUI 的登录 Token 忘了 / 和 WS Token 搞混了

两个 Token 是**两码事**：

- **WebUI 登录 Token**：登录 NapCat 网页管理台用，和第 3.2 节有关；
- **WebSocket 服务器 Token**：bot 连 NapCat 用，填在 `.env` 的 `ONEBOT_ACCESS_TOKEN`，和第 3.3 节有关。

WebUI Token 忘了：先重启 NapCat 看控制台启动日志是否会重新打印；不同版本存放位置不同（一般在 NapCat 安装目录的 config 下），以官方文档为准。**不要**把 WebUI 登录 Token 填进 `.env` 当 WS Token 用，连不上的。

---

### B6. 运行 bot 的时候能开 QQ 桌面版吗？

不能。NapCat 启动的是无界面的 QQ 客户端，和桌面版共用同一套 QQ 客户端环境，同时开容易互相冲突（可能把 NapCat 顶下线）。手机 QQ 不受影响。要用桌面版，先双击 `停止.bat`，用完再双击 `启动.bat`。

### B7. 怎么启动 / 停止

- 启动：双击项目根目录的 `启动.bat`（会自动拉起 NapCat，再启动 bot）。
- 只停 bot：在 bot 窗口按 `Ctrl+C`。
- 连 NapCat 一起停：双击 `停止.bat`。

## C. 大模型 / API

### C1. HTTP 401

Key 填错、多了空格、Key 被删、或账号没权限。重新生成一个 Key，粘贴时注意别带引号。

### C2. HTTP 402

余额不足。去平台充值；或者换一个免费/本地模型。

### C3. HTTP 429

触发限流。调低 `REPLY_RATE` / `MAX_REPLIES_PER_MINUTE` / `MAX_REPLIES_PER_HOUR`，等一会儿再试。

### C4. 连不上大模型接口

- 检查 `LLM_BASE_URL` 末尾不要多写 `/chat/completions`（代码会自己拼）；
- 公司网络/代理可能拦 HTTPS；`curl` 测一下；
- 用国内平台（硅基流动等）通常比 DeepSeek 官方更容易连；
- 用本地 Ollama：确认 `ollama serve` 在跑，`http://127.0.0.1:11434` 可达。

### C5. 模型名字写错

DeepSeek 常见的是 `deepseek-chat`（日常对话）和 `deepseek-reasoner`（推理，更贵更慢，不适合群聊）。换平台时模型名以平台文档为准。

### C6. 返回内容为空 / 只有标点

某些模型偶尔空回复；代码会跳过不发。频繁发生就换温度/换模型。

## D. 行为问题

### D1. 群里 @ 它没反应（最重要的一类）

按日志排查：

1. `npm start` 的窗口还开着吗？日志里最后一条是什么？
2. `ALLOWED_GROUPS` 里有没有这个群的群号？（最常见的原因）
3. 群里 @ 的是不是 bot 那个号？（别 @ 错人，也别 @ 你的主号）
4. `IGNORE_QQS` 有没有误伤？`QUIET_HOURS` 是不是正在静音？
5. 日志里有没有「回复失败」「OneBot 接口超时」？小号是否被禁言/被踢？
6. 大模型接口是否在报错？

### D2. 它从不主动接话，只有 @ 才回

- `REPLY_RATE` 是不是设了 0？
- 冷却中（刚回过一条，默认等 20 秒）？
- 关键词没命中？
- 群消息是不是太多，每小时配额很快用光？
- **这是正常且安全的行为**，想活跃一点再调高。

### D3. 太吵 / 刷屏

```env
REPLY_RATE=0.01
COOLDOWN_SECONDS=120
MAX_REPLIES_PER_HOUR=60
MAX_REPLIES_PER_MINUTE=2
MAX_PRIVATE_REPLIES_PER_MINUTE=2
QUIET_HOURS=1-8
```

还吵就 `REPLY_RATE=0`，只留 @ 和关键词。

### D4. 复读 / 车轱辘话

- `LLM_TEMPERATURE` 调到 1.1~1.3；
- `CONTEXT_TURNS` 别设太大（太大时它会一直盯着前文）；
- 人设里加「不要重复自己刚说过的话」。

### D5. 回复带「大肥鱼：」或 Markdown

当前版本 `sanitizeReply()` 已经处理。如果还有残留，把人设输出规则再写死一点，或自己加规则。

### D6. 同一条消息回了两遍 / 群里出现两个一样的回复

- 你是不是同时开了两个 `npm start`？
- 是不是同一个 QQ 连了两个 bot 进程？
- NapCat 里同一个 WebSocket 服务器是不是被两个客户端连了？

一个账号只保留一个 bot 实例。检查任务管理器和开着的终端窗口。

### D7. 回复很慢

正常 1~4 秒（含拟人延迟 + 模型生成）。如果超过 10 秒：

- 模型接口慢或限流；
- 上下文太长；
- 网络差；
- 日志里看「xxxxms」是模型耗时还是卡在别处。

### D8. 它说出了不该说的话

- 立刻停 bot（Ctrl+C）；
- 检查人设禁区是否覆盖；
- 加一层关键词过滤：发现敏感词直接不发送；
- 模型偶尔跑偏是常态，**不要让 bot 无人值守地在重要群里跑**。

---

### D9. 私聊会回吗？需要 @ 吗？

会回，而且私聊**不需要 @**。群聊里仍然只回 @（按当前配置）；私聊消息每一条都会直接回。
私聊同样受 `IGNORE_QQS` 黑名单、`QUIET_HOURS` 安静时段和每分钟/每小时上限约束（默认私聊 5 条/分）。私聊和群聊的上下文/记忆是分开的。
### D10. 图片、表情包、长文会处理吗？

- **图片、表情包、语音、视频、文件**：不读取，也不会触发回复；不会进记忆，不消耗 token。
- **长文字**：超过 `MAX_INPUT_CHARS`（默认 200 字）会被截断后再处理。
- **历史上下文**：每次请求最多带 `MAX_CONTEXT_CHARS`（默认 2000 字）的聊天记录，超出从最旧的开始丢。
- 这两个值都在 `.env` 里，想更省就调小。
## E. 账号与风控

### E1. 会被封号吗

有风险。第三方客户端接入不符合腾讯用户协议，被限制登录/冻结的案例存在，但不等于一定发生。**用小号、控频率、别发违规内容**是基本盘。详见 README 第 9 节和 [原理篇](原理.md) 第 10 节。

### E2. 小号被限制登录了

先停 bot，正常用手机 QQ 登录养几天；不要马上就换号继续挂。严重的话这个号就别再挂 bot 了。

### E3. 能用主号吗

强烈不建议。主号有好友、实名、支付、各种记录，一旦受限成本太高。

### E4. 能挂多少个群

技术上没限制，但建议**先 1~2 个群**，稳定后再加。群越多，消息量、成本、风控暴露面都线性上升。

## F. 费用

### F1. 一天要花多少钱

按默认参数，一个群一天大概几毛到两三块，具体取决于触发次数和上下文长度。想精确控制就调 `REPLY_RATE`、`CONTEXT_TURNS`、`MAX_REPLIES_PER_MINUTE`、`MAX_REPLIES_PER_HOUR`，并在平台后台看用量。

### F2. 有没有免费方案

- 本地 Ollama（免费，吃电脑资源）；
- 各平台的免费额度/试用；
- 把 `REPLY_RATE=0`，只在被叫到时用，次数少自然便宜。

## G. 部署与维护

### G1. 怎么让它开机自启

- 简单：把 `启动.bat` 的快捷方式放进「启动」文件夹（Win+R 输入 `shell:startup`）；
- 稳一点：用「任务计划程序」触发器选「登录时」，操作指向 `启动.bat`；
- 专业：NSSM 注册成 Windows 服务（注意工作目录设置对）；
- 也可以跑在旧笔记本/NAS/云服务器上，注意云服务器 IP 归属地可能带来额外风控；
- 云服务器/海外机器注意**时区**：`QUIET_HOURS` 按运行机器的本地时间算，服务器是 UTC 的话要自己换算（比如想要北京时间 1~7 点静音，UTC 下应设 `17-23`）。

### G2. 电脑睡眠 / 关机后 bot 还在吗

不在。NapCat 和 bot 都要保持运行。笔记本设成「插电不睡眠」，或者放到常开的设备上。

### G3. 怎么升级

```bat
cd /d <项目目录>
git pull
npm install
npm start
```

（命令在 cmd 里执行；PowerShell 里把 `cd /d` 换成 `cd`。没用 git 就跳过 `git pull`；依赖没变可以跳过 `npm install`。官方升级时同步看下 `.env.example` 有没有新增配置项。）

NapCat 升级以官方说明为准；大版本升级后先跑 `npm run doctor` 再启动。

### G4. 怎么彻底停用

停掉 `npm start` 窗口和 NapCat 进程，退出小号。想清干净就把 `data/memory.json` 删掉、`.env` 里的 Key 删掉/重置。

### G5. 能换台电脑跑吗

可以。把整个文件夹（不含 `node_modules`、`data`）复制过去，重新 `npm install`，填 `.env`，NapCat 那边重新登录小号、配同样的 WS 端口/Token 即可。

## H. 隐私与合规

### H1. 它会保存聊天记录吗

默认把每个群最近 16 条存到本地 `data/memory.json`。设 `PERSIST_MEMORY=false` 就不落盘。文件不要外传。

### H2. 怎么告诉群友

最好在群公告写一句「本群有 AI bot」；有人不愿意被记录时，尊重对方，必要时关掉 bot 或关掉持久化。

### H3. 能做商业用途吗

别。第三方协议接入本身不合规，商业用途风险更大；而且群里自动发言涉及广告合规问题。

## J. 桌面控制台（大肥鱼控制台）

### J1. 双击桌面图标没反应 / 页面打不开

1. 看端口：`netstat -ano | findstr ":8899"`。有监听就直接浏览器打开 <http://127.0.0.1:8899/>。
2. 没监听：双击 `control\启动控制台.bat`（保留黑窗口），看它报什么错。
3. 报找不到 node / node 路径变了：重新运行 `control\安装控制台.ps1`，会按当前 node 路径重新生成隐藏启动器和桌面快捷方式。
4. 端口 8899 被占用：改 `control\server.mjs` 顶部的 `PORT`，重新运行安装脚本（快捷方式不用改，它固定访问 8899，所以更推荐先找出占用端口的程序）。

### J2. 点「启动」提示 NapCat 90 秒没就绪

快速登录失效了。先双击 `napcat\start-napcat-qr.bat` 扫码登录，等 NapCat 窗口显示登录成功，再回控制台点「启动」。
如果弹出 NapCat 窗口，扫码完成后可以留着（它会自己隐藏到后台），不要重复启动。

### J3. 关掉网页后 bot 会停吗

不会。网页只是控制面板，控制台服务在后台常驻，bot 继续运行；下次双击桌面图标会重新打开页面。
想彻底停：点面板「停止」（停 bot + NapCat）；页面底部「退出控制台服务」只关控制台本身。

### J4. 控制台和 `启动.bat` 能一起用吗

不要。两者都会启动 bot，容易出现两个实例、同一条消息回两遍。日常只用桌面控制台即可，`启动.bat` 是备用/排错用。

### J5. 电脑重启后要做什么

双击桌面「大肥鱼控制台」→ 点「启动」。想开机自动跑，可以把 `启动.bat` 的快捷方式放进启动文件夹（见 G1，但会显示黑窗口），或者让我帮你把控制台服务做成开机静默启动。

### J6. 控制台的日志在哪

`data\bot.log`（bot 运行日志）、`data\napcat.log`（无界面 QQ 日志）、`data\control.log`（控制台启动/停止记录）。控制台页面只显示 bot 日志的最后一部分。

页面上的「清除日志」按钮会清空这三个文件；不会影响 bot 运行、聊天记忆，面板上的登录账号也不会丢（账号另存在 `data\account.txt`）。
### J8. 怎么让某个群不用 @ 也回 / 某个人私聊不回复

在控制台页面下方的「会话设置」里：

- 群聊：每个群选「仅 @ 回复」或「直接回复」。直接回复就是这个群所有文字消息都回，注意更费 token。
- 私聊：每个好友/私聊过的人一行「回复 / 不回复」开关；也可以手动输入 QQ 号添加。
- 每行会显示该会话「近 1 分钟 / 近 1 小时」的消息数和回复数；旁边的「每分钟 / 每小时」输入框可以单独改这个会话的限额，点「保存限额」生效。
- 每行还有「承认关系 / 装不认识」开关：切到「装不认识」后，这个群里（或这个私聊里）被问起主人兼男朋友就装不认识，不承认主人/男朋友关系；其它会话不受影响。
- 统计和限额都按会话独立计算；没单独设置的会话用 `.env` 里的默认限额。
- 改完约 2 秒生效，不用重启 bot；配置保存在 `data\chat-settings.json`。
- 列表会显示 bot 已加入的全部群 + 全部好友（+ 私聊过的人），每 15 秒自动刷新，也可以点「刷新列表」。
- NapCat 不在线时会显示上次成功读取的缓存，并标注缓存时间。
- 需要重新登录时点「扫码重新登录」，页面里会直接显示二维码，手机 QQ 扫码即可。
- 注意：图片、表情包不会触发回复；「直接回复」也受安静时段和每分钟/每小时上限限制。
### J9. bot 遇到看不懂的梗怎么办？

控制台往下拉，有「看不懂的梗」区域：

- bot 遇到真看不懂的梗会自动记一条（也会在聊天里问一句「这是什么新梗」）。
- 在对应条目里写一句解释，点「保存」；解释存进 `data/glossary.json`。
- 之后每次请求都会带上这些解释（最多 60 条），AI 下次就懂了。
- 点「忽略」是不教；已学会的条目可以「删除」。
- 如果发现它乱标梗，把那条「忽略」掉即可，不会影响聊天。

## I. 还是解决不了？

按这个顺序收集信息：

1. `node -v`、`npm -v` 的输出；
2. `npm run doctor` 的完整输出；
3. `npm start` 启动后、复现问题时的日志（把 Key 打码）；
4. NapCat 控制台/日志里的报错；
5. 卡在哪一步（连不上 / 不回 / 报错 / 回错）。

有了这五样，基本能定位。也可以对照 [原理篇](原理.md) 的数据流，从「NapCat → bot → 模型 → NapCat」一段段查。
